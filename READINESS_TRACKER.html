Already solid

Found, not just claimed
  • PII field-level encryption at rest (national ID, phone, address, spouse info, bank account)
  • Append-only, tamper-evident audit hash chain — not just an audit table
  • Double-entry general ledger
  • BCrypt password hashing at cost factor 12
  • Stateless JWT auth with MFA support and per-account lockout after failed logins
  • Security headers (HSTS, X-Content-Type-Options, Referrer-Policy), TLS 1.2/1.3 only
  • Flyway-managed schema — every database change is a reviewable, ordered migration
  • Webhook signature verification for the payments provider
  • Postgres no longer exposed on a public interface; Swagger/actuator restricted to private IPs
  • Demo admin credentials no longer created by default — gated behind real environment variables
  • Secret generation script (deploy/scripts/generate-secrets.sh) — produces strong, unique values for every key that can be randomly generated

Suggested order of operations

  1. Run ./deploy/scripts/generate-secrets.sh and load the output into your real environment (JWT_SECRET, APP_ENCRYPTION_KEY, APP_INDEX_KEY, BACKUP_ENCRYPTION_KEY, BOOTSTRAP_ADMIN_PASSWORD).
  2. Get real Flutterwave (or alternative) credentials and test the webhook path end to end.
  3. Start the credit bureau / KYC provider relationship — longest lead time, start now even though it isn't code.
  4. Commission the penetration test.
  5. Run an actual backup + restore drill and log it.
  6. Get terms, privacy, and the loan agreement in front of a lawyer.
  7. Only then: point DNS at production and go live.
